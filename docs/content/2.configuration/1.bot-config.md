---
title: Bot configuration
description: Every setting of the DiscordMute bot and how to change it.
---

The bot config is a file called `config.json` inside the `DiscordBot` folder. Rename `config.example.json` to `config.json` and fill in your values.

It only holds what the bot needs before it is connected to Discord: the token, the network and the database. Everything per server, including the plugin secret and the fallback voice channels, is set with `/setup` in Discord. See the [setup panel](/server-setup/setup-panel).

::warning
In a text like a folder path, write every backslash twice (`C:\\Path`) or use forward slashes (`C:/Path`). A single backslash breaks the file.
::

## Required settings

| Setting | Meaning |
|---------|---------|
| `token` | Your bot token from the [Discord Developer Portal](https://discord.com/developers/applications). |
| `clientId` | The application ID of your Discord bot. |

## Optional settings

| Setting | Default | Meaning |
|---------|---------|---------|
| `guildId` | none | The ID of your Discord server. With it the commands appear on that server at once. Without it they are published for every server the bot is in. |
| `botIp` | `0.0.0.0` | Where the bot listens for the plugin. Use `localhost` if the plugin runs on the same PC. |
| `botPort` | `7264` | The port the bot listens on. It must match the plugin. |
| `disableTelemetry` | `false` | Set to `true` to turn off [anonymous telemetry](/privacy/telemetry). |
| `disableUpdateCheck` | `false` | Set to `true` to turn off the [update check](/privacy/update-check). |
| `logFormat` | `pretty` | `pretty` is the colored window. `json` is for [log tools](/monitoring/json-logs). |
| `metrics` | off | Settings for [metrics](/monitoring/metrics). |

## Example

```json
{
  "token": "YOUR_BOT_TOKEN",
  "clientId": "YOUR_CLIENT_ID",
  "botIp": "localhost",
  "botPort": 7264
}
```

## Settings that moved to /setup

| Old setting | Where it is now |
|-------------|-----------------|
| `secret` | Create the plugin secret on the **General** page of `/setup`. |
| `channelIds` | Pick the fallback voice channels on the **Voice** page of `/setup`. |

Both old keys still work, so existing installs keep running, and the bot logs a hint at startup. `secret` needs `guildId` next to it. Once you have set the new values in `/setup`, remove the old keys.

To use the optional settings that are not in the example file, add them as extra lines:

```json
{
  "disableTelemetry": true,
  "disableUpdateCheck": true
}
```

## Running the hosted bot

::note
This section is for operators of a hosted bot. Players use the [hosted setup](/getting-started/hosted-setup) and need none of it.
::

| Setting | Meaning |
|---------|---------|
| `mode` | `self-host` (default) or `hosted`. In hosted mode `guildId` is not used. |
| `adminApi` | `{ "host": "127.0.0.1", "port": 9465 }`. Where the admin API listens. |
| `databaseUrl` | Required in hosted mode, together with `databaseDialect` set to `postgres` (see Advanced settings). |

Two environment variables are read besides `config.json`:

| Variable | Meaning |
|----------|---------|
| `ADMIN_API_TOKEN` | Required in hosted mode, at least 32 characters. Protects the admin API. |
| `HOSTED_TELEMETRY_TOKEN` | Lets the hosted bot send telemetry to the website. |

## Advanced settings

You can ignore these on a normal setup.

| Setting | Default | Meaning |
|---------|---------|---------|
| `databaseDialect` | `sqlite` | `sqlite` stores everything in a local file. `postgres` uses a database server. |
| `databaseUrl` | none | Address of the database server. Needed only for `postgres`. |
| `sqlitePath` | `./data/linking.sqlite` | Where the local database file is saved. |
| `clusters` | `{ "total": 1, "shardsPerCluster": 1 }` | Splits the bot over several processes. The default is right for one server. |
